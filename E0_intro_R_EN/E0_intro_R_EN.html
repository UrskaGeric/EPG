Practical 0: Setting up your system – R, RStudio and Quarto

🌐 Slovenska različica

Before the first practical

Do this practical on your own at home, before practical 1. There is no time limit. You will install the programs we use in all practicals and check that they work.

The practical has two parts:

  1. Setting up your system (Installation to Test: your first Quarto document): required. Come to practical 1 with a working system.
  2. Handbook (Handbook: R and RStudio to For comparison: Rmarkdown): a short introduction to R, RStudio and Quarto. Read it and try the examples; come back to it later whenever you need something.

Checklist for practical 1:

Installation

You need to install two programs, in this order:

Program What it is Where from
R a programming language and environment for statistics and plots https://cran.r-project.org
RStudio an integrated development environment (IDE): editor, console, plots and help in one window https://posit.co/download/rstudio-desktop/

Quarto is already included in RStudio, so you do not install it separately. We will install Git together in practical 1.

PomembnoR first, then RStudio

RStudio is only a “window” for R. It does not work without R. If you installed R or RStudio before, check that they are less than one year old, otherwise update them (install the new version over the old one).

R

  1. Open https://cran.r-project.org.
  2. Choose your operating system:
    • Windows: Download R for Windows → base → Download R-4.x.x for Windows. Run the downloaded file and install with the default settings.
    • macOS: Download R for macOS. Choose the package for your processor: arm64 for newer Macs (Apple M1, M2, M3, M4) or x86_64 for older Macs with an Intel processor (Apple menu → About This Mac). Install with the default settings.
    • Linux (Ubuntu): in a terminal, sudo apt install r-base.

RStudio

  1. Open https://posit.co/download/rstudio-desktop/.
  2. Download RStudio Desktop for your operating system (the page usually detects it).
  3. Install with the default settings.
  4. Start RStudio (not R). The console at the bottom left must show the R version, e.g. R version 4.5.1.

RStudio settings

In RStudio open Tools → Global Options → General and set:

  • untick Restore .RData into workspace at startup,
  • Save workspace to .RData on exit: Never.

This way RStudio starts with an empty environment every time. Everything you need should come from your script, not from the saved memory of a previous session. This is the basis of reproducibility: a script must also work on another computer and a year from now.

Optional: Appearance (dark theme, font size).

Course packages

R has basic functions; additional ones come in packages. We will need several in the practicals, so install them now, because the installation can take a few minutes.

Paste the following into the console in RStudio (bottom left) and run it (Enter):

install.packages(c("tidyverse", "rmarkdown", "quarto",
                   "usethis", "gitcreds",
                   "adegenet", "hierfstat", "detectRUNS"))
Package What we use it for
tidyverse working with tables and plots (ggplot2, dplyr …)
rmarkdown, quarto reports
usethis, gitcreds connecting to GitHub (practical 1)
adegenet, hierfstat population genetics (practicals 3 and 4)
detectRUNS runs of homozygosity (practical 5)

If R asks Do you want to install from sources the packages which need compilation?, answer No.

Check that the packages load:

library(tidyverse)
library(adegenet)
library(hierfstat)
library(detectRUNS)

Red messages after library() are usually just information. There is only a problem if it says Error: there is no package called …; in that case see When something goes wrong.

Test: your first Quarto document

This test checks that R, RStudio and Quarto work together.

  1. File → New File → Quarto Document…, enter the title Test and click Create.
  2. Replace the whole content of the new file with this text:
---
title: "System test"
author: "Name Surname"
format: html
---

## My first Quarto document

This is **text** in Markdown. Below is a block of R code.

```{r}
x <- c(3, 5, 2, 8)
mean(x)
barplot(x, col = "steelblue")
```
  1. Save it (Ctrl + S) as test.qmd, e.g. in your Documents folder.
  2. Click the Render button (blue arrow above the editor).

An HTML document opens with the title, the text, the result [1] 4.5 and a bar plot. If you see it, your system is ready for the practicals. You can then delete the file.

NasvetA folder for repositories

In practical 1 we will create your repository for the practicals. Already now, create a folder GitHub in your home folder (e.g. C:/Users/name/GitHub), not in OneDrive or any other folder synchronised to the cloud.

When something goes wrong

Problem Solution
RStudio reports at start-up that it cannot find R install R first (R), then restart RStudio
There is no Render button or Quarto reports an error update RStudio to the latest version
Error: there is no package called … the package is not installed: install.packages("package_name")
Installing a package reports an error about Rtools or compilation repeat the installation and answer No to the question about sources
Installing packages fails and the path contains your user name with special characters see below (Special characters in the user name (Windows))
On macOS a package does not install because of Xcode run xcode-select --install in Terminal

Special characters in the user name (Windows)

If your Windows user name contains special characters or spaces (e.g. C:/Users/Urška Novak), R often cannot install packages into the default folder. The solution is to let R use a folder without special characters:

  1. Create a folder C:/R/library.
  2. In the RStudio console run:
usethis::edit_r_environ()

If the usethis package is not installed yet, create a file .Renviron in your home folder with Notepad instead. 3. Add this line to the file, save it and restart RStudio:

R_LIBS_USER=C:/R/library
  1. Repeat the package installation (Course packages).

Handbook: R and RStudio

What is R

R is a programming language and environment for statistical analysis and plots. It was created by Ross Ihaka and Robert Gentleman in the 1990s and is now developed by a large international community. It is free and open source and runs on Windows, macOS and Linux.

Why we use it in biology:

  • reproducibility: we write the analysis down as a script that we or anyone else can rerun at any time. With point-and-click programs (e.g. Excel, SPSS) every step would have to be written down and repeated by hand;
  • packages: CRAN has more than 20,000 packages, and there are more for biology and genomics on Bioconductor and GitHub (e.g. adegenet for population genetics, ggplot2 for plots);
  • publication-quality plots, saved as PNG, PDF or SVG;
  • community: for almost every error an answer already exists (search for R + the error message, Stack Overflow).

Summary of basic commands: R cheat sheet (PDF).

How R works

R is an interpreted language: each command is executed as soon as we run it. Data, results and functions are stored in memory (RAM) as objects, each with its own name. We work on objects with operators and functions and store the results as new objects or in files (tables, plots).

Console or script

In the console a command runs as soon as you press Enter, but it is not saved anywhere. That is why we always write code in an R script (File → New File → R Script), saved as an .R file.

In a script, Enter only moves the cursor to a new line. You run code like this:

Shortcut What it does
Ctrl + Enter runs the current line (or the selected code)
Ctrl + Shift + Enter runs the whole script
Tab completes the name of an object or function
Alt + − types <-
Ctrl + S saves

On macOS use Cmd instead of Ctrl.

Comments start with #. R does not run them; you use them to describe what the code does:

# calculate the mean
x <- c(3, 5, 2, 8)  # a vector with four numbers
mean(x)
[1] 4.5

You get help for a function by putting ? in front of its name, e.g. ?mean. It opens in the Help tab.

Variables and objects

We store a value in an object with the assignment operator <-. R prints nothing; the object appears in the Environment tab. You print its content by typing the name of the object:

n_individuals <- 92
n_individuals
[1] 92
n_individuals * 2
[1] 184

Rules for object names:

  • R is case-sensitive: x and X are different objects,
  • no spaces or special characters; separate words with an underscore: eagle_data,
  • a name must not start with a number.

Functions

A function takes arguments in parentheses and returns a result:

function_name(argument1 = value1, argument2 = value2)
values <- c(1, 2, 3, 4, 5)
sum(values)
[1] 15
mean(values)
[1] 3
seq(from = 0, to = 10, by = 2)
[1]  0  2  4  6  8 10

If you do not name the arguments, R takes them in order. The help page (?seq) tells you which arguments a function has.

Packages

You install a package once (install.packages()), but you load it in every session before using it (library()):

install.packages("adegenet")   # once, in the console
library(adegenet)              # at the start of every script
Nasvet

Do not put install.packages() into a script or Quarto document, because the package would be reinstalled every time it runs. Only library() belongs in a script.

Data structures

Vector

A vector is a sequence of elements of the same type (numbers, text or TRUE/FALSE). We create it with c(). We select elements with square brackets; counting starts at 1.

countries <- c("IS", "GL", "NO", "DK", "ES")
n <- c(27, 20, 25, 16, 3)
countries[2]
[1] "GL"
n[n > 20]
[1] 27 25
length(countries)
[1] 5

Matrix

A matrix is a two-dimensional table of elements of the same type. We select an element with [row, column].

m <- matrix(1:6, nrow = 2, ncol = 3)
m
     [,1] [,2] [,3]
[1,]    1    3    5
[2,]    2    4    6
m[2, 3]
[1] 6

Data frame

A data frame is a table in which each column can be of a different type. This is the most common form of data: each row is an observation (e.g. an individual), each column a variable.

samples <- data.frame(
  country = c("IS", "GL", "NO"),
  n_individuals = c(27, 20, 25),
  island = c(TRUE, TRUE, FALSE)
)
samples
  country n_individuals island
1      IS            27   TRUE
2      GL            20   TRUE
3      NO            25  FALSE
samples$n_individuals        # one column
[1] 27 20 25
samples[samples$island, ]    # rows where island is TRUE
  country n_individuals island
1      IS            27   TRUE
2      GL            20   TRUE

Factor

A factor is a vector of categories (e.g. population, sex). The possible values are called levels.

population <- factor(c("island", "mainland", "island", "island"))
levels(population)
[1] "island"   "mainland"
table(population)
population
  island mainland 
       3        1

List

A list can contain elements of different types and lengths, even other lists. Many functions return their result as a list.

result <- list(name = "eagle", n_individuals = 92, countries = countries)
result$countries
[1] "IS" "GL" "NO" "DK" "ES"

Handbook: Quarto

Quarto is a tool that combines text, code and results (tables, plots) in one document. From a .qmd document it creates HTML, PDF, Word, a presentation or even an online book. These instructions are made in Quarto. In the practicals you will write all your reports in Quarto.

Summary: Quarto cheat sheet (PDF) and https://quarto.org.

Structure of a .qmd document

A document has three parts:

  1. the YAML header between --- and ---: title, author, output format;
  2. text in Markdown;
  3. code chunks, which start with ```{r} and end with ```.
---
title: "My report"
author: "Name Surname"
format: html
---

## Introduction

Text in **Markdown**.

```{r}
mean(iris$Petal.Length)
```

Markdown: formatting text

You type You get
# Title, ## Subtitle a level 1 and level 2 heading
**bold** bold
*italic* italic (Latin species names!)
`code` code
- item bullet list
1. item numbered list
[text](https://quarto.org) a link
![description](figure.png) a figure

RStudio also has a visual editor (the Visual button at the top left above the document), where you format text like in Word. The Source button takes you back to Markdown.

Code chunk options

You can add options at the start of a chunk; they start with #|:

```{r}
#| echo: false
#| fig-cap: "Histogram of petal lengths."
hist(iris$Petal.Length)
```
Option What it does
#\| echo: false the code is not shown in the document, but the result is
#\| eval: false the code is shown but not run
#\| include: false the code runs but nothing is shown (e.g. loading packages)
#\| warning: false, #\| message: false hides warnings and messages
#\| fig-cap: "…" figure caption

Render

The Render button (or Ctrl + Shift + K) runs all the code and creates the final document. In the background knitr runs the code and produces Markdown, and pandoc turns it into HTML, PDF or Word.

PomembnoRender starts with an empty session

When rendering, R does not see the objects you created in the console. The document must contain all the code, from library() to the last plot. If rendering reports object 'x' not found, the object exists only in the console, not in the document.

Output formats

format: Output
html a web page (default; we use this in the practicals)
pdf PDF (needs LaTeX: quarto install tinytex in the Terminal)
docx Word
revealjs a presentation

For comparison: Rmarkdown

Rmarkdown (.Rmd) is the predecessor of Quarto, and you will still often meet it in older tutorials, papers and on GitHub. The idea is the same (text + code + results); the differences are mainly in the syntax:

Rmarkdown (.Rmd) Quarto (.qmd)
Languages mainly R R, Python, Julia, bash
Button in RStudio Knit Render
Chunk options in the chunk header: ```{r, echo=FALSE} in #\| lines: #\| echo: false
Output format in YAML output: html_document format: html
Books, websites, presentations extra packages (bookdown, blogdown, xaringan) built in
Use outside RStudio limited also VS Code, Jupyter, command line

The same document in Rmarkdown would look like this:

---
title: "My report"
output:
  html_document:
    toc: true
---

```{r, echo=FALSE}
hist(iris$Petal.Length)
```

Why we use Quarto in the practicals: it is the successor of Rmarkdown, the same syntax works for reports, presentations and websites, it supports several languages and has everything built in. You can also open and run .Rmd files in Quarto, so older tutorials will not hold you back.
